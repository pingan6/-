# 安全公网部署方案

2026-10-03。本文是方案，不是已交付能力。当前仓库为 Jellyfish 衍生版，实际运行依赖 MySQL、Redis、Celery 和 RustFS；不能直接套用旧平安剧场 PostgreSQL 架构。

## 已知现状

- Vercel 前端与 PA 商标已发布；公网后台地址未配置。
- 现有后台 CRUD 缺少应用级身份验证与租户隔离，不能直接开放。
- 本机服务保留回环绑定，历史数据与环境文件不改动。
- 不接入收费模型，不创建付费资源，不降低保护。

## 推荐路线

前端继续使用现有 Vercel。后端使用能够运行现有 Docker 服务且持久保存数据的主机；保留 MySQL、Redis、worker、对象存储，避免为免费部署仓促迁移数据库或任务体系。先完成邀请制账号、项目访问范围、服务器端权限验证，再接公网 HTTPS 与受限 CORS。模型配置与密钥仅后台管理员可访问，响应和日志不能返回密钥。

账号方式、团队/租户边界和主机来源需要产品确认。尚未批准时，不增加账号业务实体、不自行选择身份供应商，不打开端口或隧道。

## 免费边界

免费前端并不等于免费完整生成平台。目前没有证据证明用户已有适用的免费常驻主机与持久存储。

Render 官方仅提供部分服务免费档：免费 web 会休眠、不能挂持久盘；免费数据库会到期，免费 Key Value 重启丢数据。因此不能把现有 MySQL/worker/媒体存储简单放入免费 web，也不能承诺永久可用。依据：[Render Free](https://render.com/docs/free)、[Background Workers](https://render.com/docs/background-workers)。

Vercel Functions 有调用执行与资源限制，不能把当前常驻 Celery worker 当作普通请求函数直接部署。依据：[Vercel Functions Limits](https://vercel.com/docs/functions/limitations)。

如必须零预算，先明确是否有可长期运行、允许联网并用于独立测试环境的现有主机。没有这类资源时，仅能保留本地完整运行和公网前端预览；不能用假数据、临时 SQLite 或关鉴权冒充公网完整产品。试用额度不等于永久免费。

## 实施顺序与验收

1. 确认身份与访问范围，列出匿名拒绝、跨账号拒绝和管理员配置访问测试。
2. 完成本地安全实现与回归，保留现有业务与媒体历史。
3. 确认主机及费用上限，备份后部署独立测试数据库/队列/存储，先验证重启后数据保留。
4. 配置 HTTPS、精确 CORS 白名单和前端后台地址；保护保持启用。
5. 验收登录、创建项目、剧本保存、分镜编辑、资产上传与访问权限、任务查询和失败恢复。
6. 真实生成另行确认模型及费用预算后验证，不将免费 Mock 通过视作真实生成通过。

每步失败停止扩展，不删除数据卷，不覆盖 .env，不将管理员共享密码嵌入前端。仍需用户确认资源与身份方案才能实施公网开放。
