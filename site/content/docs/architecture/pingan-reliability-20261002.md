# 平安科技第一轮可靠性收口

日期：2026-10-02，Asia/Shanghai。独立 Jellyfish 项目，本轮不合并原平安剧场、不改变原 PRD、不调用收费模型。

## 当前生效的修复

1. 镜头详情编辑采用一个串行保存队列。摄影参数即时保存、其他字段 1 秒防抖，共用队列，避免并行请求相互覆盖。
2. 保存状态明确区分自动保存中、已保存、保存失败。失败显示“草稿仍保留”和“重试保存”；不自动无限重试。
3. 保存请求只确认发出时的快照；等待期间的新输入保留，并在成功后继续保存。不同镜头的迟到响应不更新当前选中镜头。
4. 未保存的可编辑详情字段按镜头 ID 存入当前浏览器标签页的 sessionStorage。重新进入工作室后恢复并进行正常保存；保存成功清除备份。离开存在草稿的页面时提供浏览器提示。浏览器存储不可用会明确警告，不能保证关闭标签页后仍恢复。
5. 镜头详情加载失败提供持续错误提示及“重试加载”，不永远显示等待。缺失历史详情不会用假数据自动补齐。
6. 通用生成草稿使用同步提交锁，覆盖先派生、后提交的整个过程；重复点击不启动第二次提交。输入更改、重新加载或较新的派生请求会令旧响应失效。
7. 单镜头视频任务提交前查询已有 video-readiness，并说明未通过检查项。失败信息保留在预览窗口。信息确认状态、运行状态和生成准备度仍分离。
8. 浏览器标题、导航和项目大厅当前平台名为“平安科技”；历史资料、用户项目名称及内部兼容键没有批量改名。
9. Docker 前端编译的 Node 堆上限默认 768MB，可通过构建参数 `FRONTEND_BUILD_MAX_OLD_SPACE_MB` 覆盖。仅影响编译，不影响运行时或领域契约。

## 文件及边界

新增：`draftSave.ts`、`useShotDetailSave.ts`、`generationGuard.ts`、`videoPreflight.ts`、`front/tests/reliability.test.mjs`，位于现有工作室 hooks 和 tests 目录。

修改：`ChapterStudio.tsx`、`useGenerationDraft.ts`、前端测试入口和 UI 测试、本机 API 验收测试、前端 Dockerfile；同步当前架构及使用文档。

未修改：数据库领域结构、后端业务 API、模型供应商、导演 Prompt、原平安剧场的质量门。没有新增业务实体、模型路由、计费系统或新生产模块；OpenAPI 无变更。

此轮保存保护针对镜头详情，**不代表所有表单已具有同等恢复能力**。标题、剧本摘录等独立保存路径仍须后续验证。

## 未完成及已知问题

- 单次前端会话内防重复不等于服务端幂等；多标签页、多用户或网络未知结果后的重试尚不能保证无重复收费。
- 没有加入跨用户乐观锁，sessionStorage 不是长期备份或多端同步；不能承诺关闭标签页、清理浏览器数据后恢复。
- 断连时项目页面会显示“项目不存在”，而非准确区分网络异常与 404；确认诊断可能以 0/0 候选显示完成，与未提取状态矛盾；项目卡片统计仍需校正。
- 部分早期手工验收镜头缺少 ShotDetail。保留历史，没有批量修补；新增管理验收已包含详情立即读回断言。
- 本地视频模板预览实测出现长时间等待；直接免费接口诊断在 10 秒内未返回，记录为 ReadTimeout。未将此当作 Provider timeout，未延长预算、切换模型或付费重试。此轮不能宣布视频完整链路通过。
- 共享 Docker VM 约 4GB，第一次不限制编译内存的构建停滞；期间出现 MySQL connection lost / HTTP 500，之后免费管理测试恢复通过。编译内存受限后一次完整构建成功；资源竞争仍属本机风险，不能直接承诺生产容量。
- 真实剧情提取、图片/视频生成、取消及后期导出尚未进行本轮生产验收。未引入模型 Key，未产生模型费用。
- 企业鉴权/隔离、私有素材、备份恢复、密钥持久化安全尚不能按生产级放行。端口继续只绑定本机回环。
- 原平安剧场 F04 仍是 BLOCKED，本轮不宣布 F04 Gate Passed，也不宣布成熟生产产品。
